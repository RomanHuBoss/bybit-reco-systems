# Аудит проекта — 2026-04-04

## Что проверено
- полный pytest-baseline проекта;
- повторный deep-review sentiment ingestion и blended/global aggregation;
- целостность README / docs / env-reference;
- fail-safe поведение alerting-контура;
- устойчивость outcome-labeling к нечисловым cost-параметрам;
- smoke-компиляция Python-модулей;
- повторная сборка поставочного архива после правок.

## Найденные и исправленные проблемы

### 1. README ссылался на неполный пакет документации
**Симптом:** integrity-тест ожидал наличие `docs/audit_2026-04-04.md`, но файл и ссылка в README отсутствовали.

**Риск:** поставка выглядела завершённой, хотя формально документированный аудит ревизии отсутствовал; baseline тестов падал.

**Исправление:** добавлен этот файл и ссылка на него в README.

### 2. Alerting мог уронить цикл на битой health-строке
**Симптом:** `check_and_alert()` обращался к `s["status"]` напрямую.

**Риск:** одна частично повреждённая или legacy health-запись превращала вспомогательный контур оповещений в источник падения recommender-цикла. Это противоречит принципу fail-safe observability: деградация диагностики не должна убивать основной runtime.

**Исправление:** статус теперь нормализуется через безопасный helper. Не-dict и неполные строки больше не вызывают `KeyError`; они учитываются как «не ok», но не ломают цикл.

### 3. Outcome-labeling мог тихо получить `NaN/inf` из cost_model
**Симптом:** `_extract_cost_components()` принимал любые `float(...)`, включая `NaN/inf`.

**Риск:** нечисловая стоимость могла протечь в `_net_return`, grid-outcome и downstream calibration diagnostics, что создавало бы ложные/нефинитные `ret` и ухудшало целостность историки качества модели.

**Исправление:** добавлена finite-нормализация execution/funding cost с безопасным fallback.

### 4. Sentiment ingestion мог ложно симулировать extreme risk-off на битом upstream payload
**Симптом:** в sentiment-контуре часть веток брала внешние значения через прямой `float(...)` или без фильтрации при blended/global combine. При `NaN/inf` из внешнего источника итоговый `clamp` мог фактически увести сигнал к нижней границе или отравить общий расчёт.

**Риск:** один битый ответ внешнего sentiment-source мог создать фиктивный медвежий bias по символу или по всему рынку. Для recommendation engine это опаснее обычного отсутствия сигнала: система видит не «нет данных», а ложный strong risk-off.

**Исправление:** Fear & Greed теперь пропускается при non-finite payload, а blended/global combine учитывают только валидные source rows. Невалидная velocity нормализуется к нейтральному значению, poisoned source block больше не отравляет весь blended/global output.

## Что дополнительно покрыто тестами
- alerting устойчив к строкам health без `status`;
- alerting устойчив к недиктовым элементам в health payload;
- outcome-cost extraction нормализует `NaN/inf` к безопасным finite значениям;
- Fear & Greed источник игнорирует non-finite upstream payload;
- blended per-symbol sentiment пропускает poisoned source blocks и сохраняет finite output;
- global sentiment combine игнорирует битые source rows вместо отравления итогового market pulse.

## Логические выводы по ревизии
- Архитектура проекта в целом консистентна: есть разумное разделение data/inference/control/audit слоёв.
- Критичный execution-risk сознательно вынесен за пределы проекта; для recommendation engine это корректно отражено в документации.
- Основные найденные проблемы были не в «математике альфы», а в краевых сценариях целостности runtime и поставки. Именно такие дефекты чаще всего выстреливают в production раньше, чем базовая торговая логика.

## Рекомендации на следующую ревизию
- добрать тесты на сетевые error-paths sentiment/source adapters и ручной `/api/v1/sentiment`, так как именно там покрытие остаётся самым низким;
- при желании добавить отдельный smoke-test на operator docs package (README + docs/* + .env.example) как на единый release artifact;
- при переходе к live-эксплуатации держать отдельный paper/staging прогон с записью trade rows, иначе часть risk/control механики останется недонагруженной реальными данными.
