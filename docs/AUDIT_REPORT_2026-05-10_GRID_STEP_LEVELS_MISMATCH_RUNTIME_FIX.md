# Audit report — 2026-05-10 — GRID_STEP_LEVELS_MISMATCH runtime fix

## Контекст

После запуска системы на пустой базе у значительной части Linear USDT perpetual пар в деталях появлялось предупреждение/блокер:

- `GRID_STEP_LEVELS_MISMATCH`
- `RISK`: диапазон и `step_abs` дают примерно N-1 интервалов, а `params.grid_count/grid_levels=N`

Это чаще проявлялось на свежих рекомендациях после live Bybit preflight, когда уровни уже выровнены по `tick_size`.

## Причина

Рекомендатор строил корректную Bybit arithmetic grid-модель: `lower / upper / grid_count`, где Bybit `Number of Grids` — это число ценовых интервалов.

Но UI/execution augmentation затем независимо выравнивал по `tick_size`:

1. `range.lower` вниз;
2. `range.upper` вверх;
3. `trade_plan.levels.grid_step.step_abs` вверх.

Для сгенерированных payload с `grid_geometry_model=bybit_arithmetic_range_width_div_grid_count` это создавало рассинхронизацию: диапазон оставался прежним, а шаг мог стать чуть больше, поэтому `floor((upper - lower) / step_abs)` давал на один интервал меньше `grid_count`. В результате появлялся ложный `GRID_STEP_LEVELS_MISMATCH` для сетки, которую нужно пересобрать как цельную Bybit arithmetic-конфигурацию, а не как три независимые величины.

## Изменения

- `_snap_reco_payload_to_bybit_meta()` теперь для strict generated Bybit arithmetic payload пересобирает exchange-snapped геометрию как единую модель:
  - берёт snapped `range.lower`;
  - выбирает `step_abs`, выровненный по `tick_size` и не тоньше модельного/economic step;
  - пересчитывает `range.upper = lower + step_abs * grid_count`;
  - синхронно обновляет aliases: `params.price_range_upper`, `trade_plan.levels.range.upper`, `operator_sheet.range_upper`;
  - при необходимости выносит `kill_switch.upper` за новую верхнюю границу;
  - синхронизирует `grid_spacing_pct`, `actual_grid_step_abs`, `actual_grid_spacing_pct`.
- Legacy/manual payload без strict geometry markers оставлен в прежнем режиме, чтобы не превращать старые ручные/неполные записи в новые hard-blocks.
- Добавлена регрессия, воспроизводящая типичный случай `floor((100.2 - 99.0) / 0.101) == 11` при `grid_count=12`; после snapping диапазон расширяется до 12 точных интервалов.
